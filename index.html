How I work

Approach

01

Evals before prompts

An agent without an evaluation suite is a demo. I start from a golden dataset and the scores that matter, groundedness, relevance, task success, then gate prompt and model changes on them in CI so a regression is caught before a user finds it.

02

Permissions are part of retrieval

In an enterprise, who is asking changes what the right answer is. Access filtering belongs in the retrieval path, applied before ranking, not as a post-filter on text the model has already seen.

03

Metrics before models

Agree on the business metric and the evaluation metric that tracks it before touching a model. Fraud at 0.17% prevalence is an AUPRC problem, not an accuracy problem, and a loan model is judged at its operating threshold.

04

Monitoring and reproducibility ship together

A model goes out with its drift checks, alert thresholds and retraining trigger, plus versioned data, tracked experiments, pinned environments and CI that runs the tests. If a result cannot be rebuilt from the repository, it is not done.

Writing

Notes

Brief write-ups drawn from the work above.

Agents

Filter before you rank, not after

The tempting way to add permissions to RAG is to retrieve broadly and drop anything the user cannot see from the final answer. That quietly degrades quality: the top k is consumed by documents that get thrown away, so a permitted but lower-scoring answer never makes it into context. Pushing the access filter into the retrieval query keeps the whole budget on content the caller is allowed to read.

Evaluation

Why AUPRC, not ROC-AUC, for 0.17% fraud

At 0.17% fraud in 284,807 transactions, ROC-AUC stays flattering even when precision collapses, because the huge negative class dominates the false-positive rate. Precision and recall is the curve a fraud-ops team actually lives on, so the pipeline selects and tunes on AUPRC. See fraud-detection-mlops.

Retrieval

Two stages beat one big model

Grocery search needs both lexical relevance and behavioral signal. Asking one model for both is worse and slower than letting Vertex AI Search handle recall, then re-ranking the short candidate list with a cheap propensity model in a single batched call. The result holds a 152 ms p95 on Cloud Run, and falls back to retrieval order if the endpoint is unavailable. See grocery-search-vertex.

Knowledge graphs

Graph plus vector for structured domains

University data has explicit relationships, program to department to requirement, that pure embedding search flattens. The chatbot pairs a Neo4j graph lookup with embedding similarity so answers are grounded in both the structure and the text. See RAG-Chatbot-1.
