02 Credit Card Fraud Detection: Production MLOpsxgboost · auprc · psi drift · AUPRC 0.765 vs 0.718 Complete
Problem

284,807 transactions at 0.17% fraud, a 1:578 imbalance. Accuracy is meaningless at that prevalence, and a random split leaks the future into training.

Approach

Evaluate the way production does: a chronological 70/15/15 split, model selection on AUPRC rather than ROC-AUC, and an operating threshold frozen on validation against a precision budget.

Architecture
chronological split -> XGBoost vs logistic baseline -> MLflow tracking -> artifact ships with threshold + metrics + data checksum -> FastAPI scoring service in Docker -> PSI drift monitor // 10 CI tests on a synthetic model
Measured result
Test AUPRC 0.765 against 0.718 for the logistic baseline, ROC-AUC 0.979, threshold set for a 0.90 precision budget. PSI flags a large shift in feature V1 between validation and test (PSI 1.57), consistent with the precision drop seen across those splits.

03 Grocery Product Search and Re-ranking on GCPvertex ai search · cloud run · 152 ms p95, 9,162 products Complete
Problem

Grocery search needs both lexical relevance and behavioral signal. Asking a single model to carry both is slower and worse than splitting the job.

Approach

Two stages: Vertex AI Search handles recall over the catalog, then a gradient boosting re-ranker scores reorder propensity for the short candidate list in one batched call, blended 0.7 relevance to 0.3 propensity.

Architecture
Instacart orders -> Cloud Storage + BigQuery -> Vertex AI Search structured data store -> re-ranker in Vertex AI Model Registry -> Vertex AI endpoint -> FastAPI on Cloud Run blends both scores // falls back to retrieval order if the endpoint fails
Measured result
152 ms p95 end to end on Cloud Run (123 ms median) over 9,162 products, with the re-ranker at 27% lower test MAE than a mean-prediction baseline (0.0930 against 0.1279).

05 Lending Club Loan Default Predictionthreshold tuning · imbalance · ROC-AUC > 0.85 Complete
Problem

Roughly 38k loans at a 1:5.8 imbalance, 32k repaid against 5.5k defaulted. Accuracy rewards a model that simply predicts repayment every time.

Approach

Compare four models on one split and judge them on ranking quality and the operating point a lender would actually approve on, not on a default 0.5 cut.

Architecture
borrower + loan + credit-bureau features -> LogReg / Tree / Random Forest / XGBoost -> class-imbalance treatment -> threshold selection at the lender operating point -> grade-level default rates as a sanity check // ~95% repayment at grade A, 67% at grade G
Measured result
ROC-AUC above 0.85 on held-out loans, with gradient boosting giving the best true positive rate at a fixed false positive rate, and precision and recall reported at the chosen threshold so the cost of a missed default is explicit.

Approach

01

Evals before prompts

An agent without an evaluation suite is a demo. I start from a golden dataset and the scores that matter, groundedness, relevance, task success, then gate prompt and model changes on them in CI so a regression is caught before a user finds it.

02

Permissions are part of retrieval

In an enterprise, who is asking changes what the right answer is. Access filtering belongs in the retrieval path, applied before ranking, not as a post-filter on text the model has already seen.

03

Metrics before models

Agree on the business metric and the evaluation metric that tracks it before touching a model. Fraud at 0.17% prevalence is an AUPRC problem, not an accuracy problem, and a loan model is judged at its operating threshold.

04

Monitoring and reproducibility ship together

A model goes out with its drift checks, alert thresholds and retraining trigger, plus versioned data, tracked experiments, pinned environments and CI that runs the tests. If a result cannot be rebuilt from the repository, it is not done.

Notes

write-ups drawn from the work above
Agents

Filter before you rank, not after

The tempting way to add permissions to RAG is to retrieve broadly and drop anything the user cannot see from the final answer. That quietly degrades quality: the top k is consumed by documents that get thrown away, so a permitted but lower-scoring answer never makes it into context. Pushing the access filter into the retrieval query keeps the whole budget on content the caller is allowed to read.

Evaluation

Why AUPRC, not ROC-AUC, for 0.17% fraud

At 0.17% fraud in 284,807 transactions, ROC-AUC stays flattering even when precision collapses, because the huge negative class dominates the false-positive rate. Precision and recall is the curve a fraud-ops team actually lives on, so the pipeline selects and tunes on AUPRC. See fraud-detection-mlops.

Retrieval

Two stages beat one big model

Grocery search needs both lexical relevance and behavioral signal. Asking one model for both is worse and slower than letting Vertex AI Search handle recall, then re-ranking the short candidate list with a cheap propensity model in a single batched call. The result holds a 152 ms p95 on Cloud Run, and falls back to retrieval order if the endpoint is unavailable. See grocery-search-vertex.

Knowledge graphs

Graph plus vector for structured domains

University data has explicit relationships, program to department to requirement, that pure embedding search flattens. The chatbot pairs a Neo4j graph lookup with embedding similarity so answers are grounded in both the structure and the text. See RAG-Chatbot-1.
